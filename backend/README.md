# cokoyo-backend

`docs/v1-poc.html` の v1 PoC 仕様の実装。

フロントと DTC API の間に立って、**scope と block を判定してから MAC に変換する**層。
MAC はこの層から外に出ない。

## 動かす

```sh
npm install
npm run dev          # http://localhost:8080
npm test             # 19件
npm run typecheck
```

DB は `DB_PATH` の SQLite ファイル1つ。起動時にテーブルを作るのでマイグレーションの手順はない。
`node:sqlite`（Node 24 標準）を使っているのでネイティブビルドは発生しない。**Node 24 以上が必須。**

## 環境変数

`.env.example` を参照。重要なのは2つ。

| | |
|---|---|
| `MOCK_DTC` | `1` で実APIを叩かず、MACから決定的に在校を組み立てる。既定は `0` |
| `TIMING_FLOOR_MS` | 応答時間の下限。ブロックを速さの差で悟られないようにする（仕様06） |

## DTC API について

`https://api.dtc.wide.ad.jp` の `GET /wifi/clients/{mac}/connection` を使う。認証は無い。

実装上、次の3点を吸収している。

- **書式**：DTC はコロン区切りしか受け付けない。DBには区切りなし12桁で持ち、送信直前だけ整形する
- **404**：観測が無いMACは `NOT_FOUND`。**`present: false` に潰す**。そのまま流すと「観測なし」と「いない」が区別できてしまう
- **503**：SNMP の取り込み中。400ms・800ms と二度粘る

**履歴は絶対に取りに行かない。** DTC は時間範囲を渡すと最大7日分を返すが、認証が無いため、
これを中継すると移動の軌跡がそのまま漏れる。常に最新1件だけを取る。

### 観測が無いMACは 404 ではなく 503 が返る

実測したところ、**観測が一度も無いMACは恒久的に 503**（`SNMP client observations are still being processed.`）
を返す。DTC 側は「未パースのスナップショットが存在するか」で 503 を判定しており、
観測が無いMACではその比較対象が無いため、古い未パースが1件でも残っている限り 503 のままになる。

そのため 404 だけを当てにできない。リトライしても 503 のままなら `unavailable` として扱い、

- その相手は **`present: false`** に倒す（「いない」と同じ形にしないと、未登録のMACを持つ相手だけ見え方が変わる）
- レスポンス全体に **`degraded: true`** を立てる（どの相手だったかは示さない）

UI はこのフラグを見て「いない」ではなく「確認できませんでした」と出すとよい。

**sfc-icar に報告する価値がある挙動**。古い未パースのスナップショットを埋めるか、
観測が無いMACは 404 を返すようにしてもらえれば、この経路は不要になる。

## 仕様書からの変更点

実装時に判断を変えたところ。`docs/v1-poc.html` にも反映済み。

1. **`secret` は平文で保存せず sha256 で持つ。**
   結果として再登録では同じ secret を返せないので、**新しい secret を発行する**。
   `share_key` は変えないので、フレンドへの配り直しは発生しない。
   「再登録すると前の端末はログアウトされる」という挙動になる。
2. **自分自身は常に見える。** 自分の `share_key` を問い合わせると在校が返る（フロントの表示用）。

## デプロイ

`deploy/docker-compose.yml` を参照。`api` はホストにポートを開かず、Caddy 経由だけで届く。

```sh
cd deploy && docker compose up -d --build
```
