00通行証とMACの関係

通行証はMACの別名でも、MACを暗号化したものでもない。 ただの番号で、意味を持つのは大学APIの台帳の中だけ。 台帳が「その番号 → 誰の / どの範囲 / 有効か」を覚えていて、そこから先で初めてMACに行き着く。

MACアドレス

端末そのものの名前。1台に1つしかなく、誰が持っても同じ意味を持ち、範囲も期限もなく、渡したら取り消せない。だから配らない。

通行証

「この人に、この範囲だけ、取り消すまで聞いてよい」という許可。相手ごとに何枚でも作れて、1枚ずつ範囲を変えられ、1枚ずつ捨てられる。

01端末は2種類ある

同じ①アプリ層でも、持っている鍵が違う端末は別物として扱う。 自分の端末は「本人トークン」で自分の設定を変えられ、相手の端末は「通行証」で見るだけ。 この2つを1本のレーンにまとめると、何が誰にできるのかが読めなくなる。

自分のスマホ

見られる側 — 在校情報の持ち主
本人トークン
  • 本人登録（自分のMACを紐付ける）
  • 通行証を発行する・1枚だけ無効化する
  • 見せる範囲を決める（キャンパス / 建物）
  • かくれんぼをオン / オフ
  • 自分のMACはアプリからは取れない（本人はOS設定で読めるが、アプリに渡す必要はない）
⇄

フレンドのスマホ

見る側 — 通行証をもらった相手
通行証
  • もらった通行証を保存しておく
  • アプリを開いたときに在校を問い合わせる
  • 返るのは許された範囲だけ
  • 相手のMACは一生わからない
  • 無効化されたら何も取れなくなる
ただし同じ端末が両方をやる。 自分の在校については「見られる側」、フレンドの在校については「見る側」。 役割が2つあるだけで、配るアプリは1種類。以下の図では、話を追いやすいように左2レーンに分けて描いている。

06大学APIにお願いしたい機能

本人トークンで呼ぶものが1・2・4、通行証で呼ぶものが3。この4本で上の図がすべて成立する。

API 1 — 本人トークン

本人登録

学内Wi‑Fiに繋いだ状態でアクセスすると、そのMACアドレスを本人のものとして登録する（他人のMACで登録されるのを防ぐため）。

API 2 — 本人トークン

通行証の発行・無効化・範囲設定

フレンドごとの通行証を発行／無効化し、見せる範囲（キャンパス / 建物）を設定する。

API 3 — 通行証

在校の問い合わせ

通行証を渡すと、範囲内で「いる / いない」を返す（ベストフレンドには建物も）。

API 4 — 本人トークン

かくれんぼ オン / オフ

本人が設定すると、以降すべての問い合わせに「いない」を返す。

難しければ、まずは「このMACアドレスはいるか」の1本だけでも試作は進められる。 上の仕組みは大学API模擬の試作品で一通り動作確認済み（1人だけの解除・ベストフレンド・かくれんぼ・ポイント）。
