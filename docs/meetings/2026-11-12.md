## 話したこと

### UI/UX とオンボーディング

- 文字が多く垢抜けない。洗練が要る。
- WiFi のつなぎ方を、動画や案内でアプリ内に出す。
- MAC アドレスをボタン一つで登録できないか（IP と MAC の紐付け）。技術的にできるかは未確認。
- オンボーディングにプッシュ通知をオンにする画面があるか確かめる。
- 「YO！」に加えて「会おう」のようなボタン案。ボタンは増やさず、リアクションのボタン一つから選択肢（YO！・会おう など）が開く形がよい。実際に会うところまで伴走する、という狙い。

### フレンドが少ない問題

- フレンドがいなくても開く理由を作る：今日キャンパスに何人いるかを匿名で出す。背景にスライムがうじゃうじゃいる見せ方。
- 「知り合いかも」の候補を定期的に入れ替える。
- オフラインのイベントと、既存のコミュニティとの連携で知ってもらう（コラボイベント、授業後の宣伝など）。
- アプリにイベントのタブを足し、当日のイベントを開いたときに出す案。
- SNS の投稿で、休眠している人にもう一度開いてもらう。

### ポイント・ミニゲーム・スライムのスキン

- ポイントを「欲しい」と思える状態を作るのが最重要。在校確認やフレンド追加・招待で貯まり、スキンやアイテム、育成に使う。
- ミニゲーム「ここよクエスト」（仮）：在校確認で会えたフレンドのスライムでダンジョンを進む、すれちがい通信風のゲーム。スキンの色が属性。1 日 1 回、在校確認が条件。
- 女性向けには育成やパズルが向くという話。着せ替えはあつ森のような世界観を目指す。
- 実績：5 日連続で来る、深夜にいる、辺鄙な場所に来る、などでスキンや称号が開く。カッパ池によく来る人にカッパのスキンなど、SFC らしいもの。

### コンセプトと方向性

- ミッションを一言で言えるようにする。候補：「つながると、もっと楽しい」「大学に行くのが憂鬱じゃなくなる」。デジタルの時代だからこそ、対面で会うことに価値がある。
- チャット：LINE と違い、SFC というキャンパスに結びついたチャットなら独自の価値がある。ただしサーバーの負荷と UI の複雑化が心配。
- ランディングページを作る（スライムを使った、ポップでカラフルなもの）。
- 別アプリの構想はいったん保留し、ここよに集中する。
- ゲーム系の機能は、来年の新入生の時期を目標に出す。
- 新入生は友達が欲しいので刺さる。WiFi のつなぎ方の案内とセットで届ける。

### MAC アドレスを自動で取れないか（whoami エンドポイントの話）

- キャンパスの WiFi は同じセグメントではない。KM・CNS・eduroam の 3 つのセグメントがあり、割り当てはランダム（？）。
- 同じセグメントなら IP から MAC アドレスを引けるかもしれないが、セグメントが違うと無理。
- 大学のネットワーク側の SNMP（IP と MAC の対応表）を経由すればできる？ → 大学に打診する。
- SSID と何かで認証する方法？
- 現実的な線：端末の設定画面へ誘導する。
