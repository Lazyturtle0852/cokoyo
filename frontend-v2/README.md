# frontend-v2

COKOYO のアプリ画面（React + Vite + TypeScript）。

2026-09-15 にグループで決めた画面の仕様をもとにしたもの。本番（`cokoyo.lazyta-toru.net`）で動いているのはこれ。
バックエンドが未接続のときはブラウザの中の模擬バックエンドで一通り動く。既存の `frontend/`（仮実装）とは別に置いてある。

## 動かす

```sh
cd frontend-v2
npm install
npm run dev          # http://localhost:5173
npm run build        # 型チェック → dist/
npm run typecheck
```

開発中は説明用の外枠で出る。画面の右側に「デモ操作」（キャンパスの様子・天気・相手の操作を変える）、
「バックエンドとの通信」（送った内容と返ってきた内容）、「DBの中身」が並ぶ。本番の見た目は `?shell=app`。

## 画面

| 画面 | 内容 |
|---|---|
| ホーム | キャンパスのフィールド（在校している自分とフレンドがスライムで出る。かくれんぼ中の自分はおばけ。フレンドのスライムを連打すると「つんつん」が届く）、「ポイント獲得（在校確認）」ボタン、フレンドの在校、今日の獲得、かくれんぼ |
| 地図 | ホームの「地図」から。建物（OpenStreetMap から起こした形）ごとに、そこにいるベストフレンドのスライム |
| フレンド | 追加（「QR」タブ：自分のQRと、カメラで相手のQRを読み込む／「リンクで共有」タブ：招待リンク・共有キー・キーやMACアドレスの入力）、届いた申請の承認、ベストフレンドの申請・承認・解除、ブロックと解除、かくれんぼ |
| 地図 | ホーム上部のキャンパスの図の「地図」ボタンから。だれがどの建物にいるかを、SFC のかたちに並べた地図の上にスライムで出す。建物が見えるのはベストフレンド同士のときだけで、それ以外の在校中の人は「キャンパスのどこか」にまとめる |

## ホーム画面に追加（PWA）

スマホのホーム画面に置くと、ブラウザの枠なしの全画面で開ける。

| ファイル | 中身 |
|---|---|
| `public/manifest.webmanifest` | アプリの名前・アイコン・全画面で開く設定。パスはすべて相対にしてあるので、`/` でも `/explain/` でも `/test/` でもそのまま動く |
| `public/sw.js` | サービスワーカー。Android の Chrome に「追加できる」と認めてもらうためと、電波が無いときに前の画面を出すためだけのもの。必ずネットワークを先に見る。`/api/` は控えない |
| `public/icon-*.png`, `apple-touch-icon.png` | アイコン。`node tools/make-icons.js` で作り直せる（スライムのドット絵をそのまま描いている） |
| `src/app/install.ts` | 追加ずみか、追加できるか、どう案内するか |

案内の出しかたは端末で変わる。Android の Chrome は `beforeinstallprompt` を預かってボタン1つで追加、
iPhone は共有メニューからしか追加できないので手順を出す。パソコンでは出さない。
はじめて開いた人には登録のいちばん最初に出し、登録ずみの人にはホームのいちばん上にカードで出す。
「あとで」を押すと以後は出さない（`localStorage` の `cokoyo-install-skipped:v1`）。

**カメラとサービスワーカーは https でしか動かない。** 本番（`cokoyo.lazyta-toru.net`）と
手元の `localhost` は大丈夫だが、`192.168.x.x` のような生のIPで開くと動かない。

## 招待リンクと、アプリの中のブラウザ

招待リンクは `?add=<共有キー>` に加えて `openExternalBrowser=1` を付ける。
LINE はこれが付いたリンクを、アプリの中の小さなブラウザではなく**ふだん使っているブラウザ**で開く。

アプリの中のブラウザ（LINE・インスタなど）は Safari や Chrome とは別ものとして扱われるので、
そこで登録すると**同じ人のアカウントが2つ**できてしまう。フレンドの申請も片方にしか届かない。
`src/app/browser.ts` で見分けて、登録の画面に「ふだんのブラウザで開いてください」の案内を出す
（Android は Chrome で開き直すボタン、iPhone は手順）。この状態では「ホーム画面に追加」の案内は出さない。

## フレンドの状態を取り直す

フレンドは相手の操作でも変わる。自分が何かするまで古いままだと、
片方の画面にだけ「承認待ち」が残って見える。

- 画面に戻ってきたとき（`visibilitychange` / `focus`、5秒に1回まで）に裏で取り直す
- 自分のQRを出しているあいだは3秒ごとに見にいき、フレンドが増えたら知らせてシートを閉じる
- どちらも「バックエンドとの通信」には記録しない（直前の操作の記録を汚さないため）

## 入れたままにする（再ログインを求めない）

一度登録したら、同じ端末では入れたままにする。

1. 端末トークンは `localStorage`（`cokoyo-device:v1`）と、バックエンドが付けるクッキーの両方にある
2. 登録に使ったMACアドレスも同じ場所に覚えておく
3. それでもトークンが効かなくなったら（401）、覚えているMACで `POST /v1/sessions` を黙って呼び、元の1回を送り直す（`src/api/client.ts` の `recoverSession`）
4. MACの覚えも無いときだけ、引き継ぎの画面を出す

設定タブの「ログアウト」は、この覚えを全部消す（`device.forget()` と `DELETE /v1/sessions`）。

## 接続先

次の順で決まる。どれも無ければ模擬バックエンド。

1. URLの `?api=<URL>`（例 `http://localhost:5173/?api=http://localhost:8080`）
2. 環境変数 `VITE_API_BASE_URL`（`.env.local`）

## バックエンドとの契約

`src/api/types.ts` と `shared/app-types.ts` は**同じ形**になっている。ずれたら
`backend/test/contract.test-d.ts`（`cd backend && npm run typecheck`）が型エラーで落ちる。
エンドポイントの一覧と、ポイント・振り分けの決まりは `docs/api-for-backend.md`。

本番はフロントとAPIが同一オリジンなので CORS は要らない。開発中は Vite の dev proxy が同じ役割をする。

```sh
cd backend && npm run dev            # http://localhost:8080
cd frontend-v2 && npm run dev        # http://localhost:5173/?api=/api
```

## 外枠（`VITE_SHELL`）

同じソースから2つの見た目を作る。

| `VITE_SHELL` | 見た目 | 使う場所 |
|---|---|---|
| `app` | アプリだけ。スマホ枠・偽のステータスバー・説明は出さない | 本番（`/`） |
| `explain`（既定） | 左にスマホ枠、右に「デモ操作」「バックエンドとの通信」「DBの中身」 | `/explain`、`/test`、開発中 |

`?shell=app` を付ければ、ビルドし直さずに本番の見た目を確認できる。

「DBの中身」は `GET /v1/debug/db` を叩いて、SQLite の行をそのまま並べる。PoC なのでテーブル丸ごと・全員ぶんで、
端末トークンも要らない。伏せてあるのは `mac` だけ（MAC が事実上のパスワードのため）。この通信は
「バックエンドとの通信」には記録しない（直前の操作の記録を汚さないため）。模擬バックエンドにはDBが無いので、
`/test` では代わりに案内だけ出る。
